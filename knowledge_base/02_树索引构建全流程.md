# 02 · LLM 如何把 PDF 变成树索引：全流程代码拆解

核心思想一句话：**不让 LLM 直接"输出一棵树"，而是把 PDF 每页打上页码标签喂给 LLM，让它输出一份带层级编号的"扁平目录"，机器校验、修复后再确定性地组装成树。**

入口链路：`run_pageindex.py` → `page_index_main()` → `tree_parser()` → `meta_processor()` → 建树。

---

## 第 0 步：页面打标签 —— 让 LLM 能"报告页码"

LLM 看不见 PDF 的页码，所以先把每页文本用 `<physical_index_X>` 标签包起来。

> 源码：`pageindex/page_index.py:676-683`（`process_no_toc` 开头）

```python
def process_no_toc(page_list, start_index=1, model=None, logger=None):
    page_contents=[]
    token_lengths=[]
    for page_index in range(start_index, start_index+len(page_list)):
        page_text = f"<physical_index_{page_index}>\n{page_list[page_index-start_index][0]}\n<physical_index_{page_index}>\n\n"
        page_contents.append(page_text)
        token_lengths.append(count_tokens(page_text, model))
```

喂给 LLM 的文本长这样：

```
<physical_index_5>
3. Financial Stability
The Federal Reserve monitors ...
<physical_index_5>

<physical_index_6>
3.1 Monitoring Financial Vulnerabilities
...
<physical_index_6>
```

两个细节：

- `page_list` 是 `get_page_tokens()`（`pageindex/utils.py`）返回的 `[(page_text, token_len), ...]`，**token 数在解析 PDF 时一次性预计算**，后面分组、判断大节点都直接复用，不重复计算。
- `start_index` 参数让这段逻辑可以处理"从第 37 页开始的子文档"——这是后面**递归细分大节点**能复用同一套代码的关键。

## 第 2 步：LLM 生成"扁平目录"

所有路线的产出都是同一种中间格式——**扁平列表，层级用 `"1.2.3"` 编号字符串表达**：

```json
[
  {"structure": "1",   "title": "Introduction",              "physical_index": 2},
  {"structure": "2",   "title": "Financial Stability",       "physical_index": 5},
  {"structure": "2.1", "title": "Monitoring Vulnerabilities", "physical_index": 6}
]
```

为什么不让 LLM 直接输出嵌套 JSON 树？扁平列表 + 编号字符串比深层嵌套更不容易被 LLM 写坏（括号配对、截断后无法拼接等问题），且方便逐条校验和修复。

### 路线 C（无 TOC）：分组 + 初始生成 + 增量续建

**先切组**——全文塞不进一个 prompt：

> 源码：`pageindex/page_index.py:515-548`（`page_list_to_group_text`，节选）

```python
def page_list_to_group_text(page_contents, token_lengths, max_tokens=20000, overlap_page=1):    
    num_tokens = sum(token_lengths)
    if num_tokens <= max_tokens:
        return ["".join(page_contents)]

    expected_parts_num = math.ceil(num_tokens / max_tokens)
    average_tokens_per_part = math.ceil(((num_tokens / expected_parts_num) + max_tokens) / 2)
    
    for i, (page_content, page_tokens) in enumerate(zip(page_contents, token_lengths)):
        if current_token_count + page_tokens > average_tokens_per_part:
            subsets.append(''.join(current_subset))
            # Start new subset from overlap if specified
            overlap_start = max(i - overlap_page, 0)
            current_subset = page_contents[overlap_start:i]
            current_token_count = sum(token_lengths[overlap_start:i])
        current_subset.append(page_content)
        current_token_count += page_tokens
```

两个非显易见的设计：

- **均衡切分**：阈值不是直接用 `max_tokens`，而是取"平均份额与上限的中点"（`average_tokens_per_part`）。否则 41000 token 的文档会被切成 20000+20000+1000 —— 最后一组只有零头，上下文严重不均。
- **相邻组重叠 1 页**（`overlap_page=1`）：防止章节标题恰好卡在切分边界上被两边都漏掉。

**第一组用 `generate_toc_init`**（完整 prompt）：

> 源码：`pageindex/page_index.py:642-674`

```python
def generate_toc_init(part, model=None):
    prompt = """
    You are an expert in extracting hierarchical tree structure, your task is to generate the tree structure of the document.

    The structure variable is the numeric system which represents the index of the hierarchy section in the table of contents. For example, the first section has structure index 1, the first subsection has structure index 1.1, the second subsection has structure index 1.2, etc.

    For the title, you need to extract the original title from the text, only fix the space inconsistency.

    The provided text contains tags like <physical_index_X> and <physical_index_X> to indicate the start and end of page X. 

    For the physical_index, you need to extract the physical index of the start of the section from the text. Keep the <physical_index_X> format.

    The response should be in the following format. 
        [
            {{
                "structure": <structure index, "x.x.x"> (string),
                "title": <title of the section, keep the original title>,
                "physical_index": "<physical_index_X> (keep the format)"
            }},
            
        ],

    Directly return the final JSON structure. Do not output anything else."""

    prompt = _SYSTEM_HARDENING + prompt + '\nGiven text\n:' + _secure_doc_text(part)
    response, finish_reason = llm_completion(model=model, prompt=prompt, return_finish_reason=True)

    if finish_reason == 'finished':
         return extract_json(response)
    else:
        raise Exception(f'finish reason: {finish_reason}')
```

prompt 里把 LLM 的三个子任务都约束死了：`structure`（层级编号规则用例子教）、`title`（"keep the original title, only fix the space inconsistency"——禁止改写，后面验证环节要拿标题去原文模糊匹配）、`physical_index`（"Keep the format"——输出必须是 `<physical_index_X>` 字面量，方便后续用正则严格校验）。

**后续组用 `generate_toc_continue` 增量续建**（`pageindex/page_index.py:602-639`）：prompt 额外把"前面已生成的树"作为上下文带上，要求 *"Directly return the additional part"*，只输出新增条目。主循环在 `process_no_toc`（`:699-716`）：

关键的 offset 计算——**取众数而非平均值**，对 LLM 定位错一两个标题天然鲁棒：

> 源码：`pageindex/page_index.py:483-503`

```python
def calculate_page_offset(pairs):
    differences = []
    for pair in pairs:
        try:
            difference = pair['physical_index'] - pair['page']
            differences.append(difference)
        except (KeyError, TypeError):
            continue
    if not differences:
        return None
    difference_counts = {}
    for diff in differences:
        difference_counts[diff] = difference_counts.get(diff, 0) + 1
    most_common = max(difference_counts.items(), key=lambda x: x[1])[0]
    return most_common
```

其中 `toc_transformer`（`pageindex/page_index.py:364-425`）负责把目录原文转 JSON，内置**截断续写循环**：输出不完整就带着 `chat_history` 追问 *"Please continue ... from where you left off"*，最多 5 轮拼接，每轮用另一个 LLM 判断 `check_if_toc_transformation_is_complete`（`:216-235`）验收。

### 路线 B（有 TOC 无页码）：LLM 逐组填页码

`process_toc_no_page_numbers`（`pageindex/page_index.py:724-775`）：目录结构已知（同样先过 `toc_transformer`），只缺页码。把全文分组，每组让 LLM 对照结构填 `physical_index`（`add_page_number_to_toc`，`:550-586`）。这条路线有最严格的防篡改校验（见 04 篇：LLM 改了条目顺序直接抛 `ValueError`）。

## 第 4 步：确定性建树（不用 LLM）

总控在 `tree_parser`（`pageindex/page_index.py:1194-1228`）：

- `add_preface_if_needed`（`pageindex/utils.py:373-384`）：如果第一个章节不从第 1 页开始，插入一个 `{"structure": "0", "title": "Preface", "physical_index": 1}` 节点，保证树覆盖每一页。
- `check_title_appearance_in_start_concurrent`（`pageindex/page_index.py:142-169`）：并发问 LLM 每个标题是不是在页面**开头**，结果存进 `appear_start` 字段。

这个 `appear_start` 决定相邻章节要不要**共享边界页**：

> 源码：`pageindex/utils.py:434-453`（`post_processing`）

```python
def post_processing(structure, end_physical_index):
    # First convert page_number to start_index in flat list
    for i, item in enumerate(structure):
        item['start_index'] = item.get('physical_index')
        if i < len(structure) - 1:
            if structure[i + 1].get('appear_start') == 'yes':
                item['end_index'] = structure[i + 1]['physical_index']-1   # 下一节从页首开始，不共享
            else:
                item['end_index'] = structure[i + 1]['physical_index']     # 下一节从页中开始，共享该页
        else:
            item['end_index'] = end_physical_index
    tree = list_to_tree(structure)
```

## 第 5 步：递归细分大节点 —— 树的深度是"长"出来的

> 源码：`pageindex/page_index.py:1165-1192`（`process_large_node_recursively`，节选）

```python
async def process_large_node_recursively(node, page_list, opt=None, logger=None):
    node_page_list = page_list[node['start_index']-1:node['end_index']]
    token_num = sum([page[1] for page in node_page_list])
    
    if node['end_index'] - node['start_index'] > opt.max_page_num_each_node and token_num >= opt.max_token_num_each_node:
        node_toc_tree = await meta_processor(node_page_list, mode='process_no_toc',
                                             start_index=node['start_index'], opt=opt, logger=logger)
        ...
        if valid_node_toc_items and node['title'].strip() == valid_node_toc_items[0]['title'].strip():
            node['nodes'] = post_processing(valid_node_toc_items[1:], node['end_index'])
            ...
    if 'nodes' in node and node['nodes']:
        tasks = [process_large_node_recursively(child_node, page_list, opt, logger=logger)
                 for child_node in node['nodes']]
        await asyncio.gather(*tasks)
```

要点：

- 触发条件是 **AND**：超过 `max_page_num_each_node=10` 页**且** `max_token_num_each_node=20000` token 才细分（页多但内容稀疏的节点不值得切）。
- 把节点的页面切片当"小文档"，**重跑 `meta_processor(mode='process_no_toc', start_index=node['start_index'])`**——前面铺垫的 `start_index` 参数在这里闭环。
- 开头的 `node['title'] == valid_node_toc_items[0]['title']` 判断是去重：子文档的第一个标题往往就是节点自身，避免生成 "Chapter 3 → Chapter 3" 的自嵌套。
- 对所有子节点 `asyncio.gather` 并发递归。

## 第 6 步：编号与摘要

async def generate_summaries_for_structure(structure, model=None):
    nodes = structure_to_list(structure)
    tasks = [generate_node_summary(node, model=model) for node in nodes]
